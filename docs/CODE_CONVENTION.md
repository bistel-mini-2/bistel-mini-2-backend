# Code Convention

이 문서는 FastAPI + LangChain 기반 백엔드 코드를 작성할 때 지킬 규칙을 정리합니다.

## Python/FastAPI 기본 규칙

- Python 코드는 4 spaces 들여쓰기를 사용합니다.
- 함수명과 변수명은 `snake_case`를 사용합니다.
- 클래스명은 `PascalCase`를 사용합니다.
- 상수는 `UPPER_SNAKE_CASE`를 사용합니다.
- 의미가 분명한 이름을 사용하고, 축약어는 꼭 필요한 경우에만 사용합니다.
- 로그는 `print` 대신 `logging` 사용을 권장합니다.
- 예외 처리는 FastAPI의 `HTTPException` 또는 공통 예외 처리 방식으로 정리합니다.

## 파일/폴더 네이밍

- 파일과 폴더는 소문자와 `_`를 사용하는 `snake_case`를 기본으로 합니다.
- 도메인별 코드는 `api/{domain}` 하위에 배치합니다.
- 공통 유틸리티는 `api/common` 하위에 배치합니다.
- 정책 관련 코드는 `api/policy` 하위에 배치합니다.
- 추천 관련 코드는 `api/recommend` 하위에 배치합니다.
- RAG 관련 코드는 `api/rag` 또는 별도 서비스 계층으로 분리합니다.

## 라우터, 서비스, 스키마 분리 기준

- 라우터는 HTTP 요청/응답 처리와 의존성 연결만 담당합니다.
- 서비스는 비즈니스 로직, LangChain 호출, 외부 API 호출을 담당합니다.
- 스키마는 요청/응답 모델과 검증 규칙을 담당합니다.
- 기능이 커지면 `router.py`, `service.py`, `schema.py`처럼 역할별 파일로 분리합니다.
- 작은 기능이라도 라우터에 비즈니스 로직을 길게 넣지 않습니다.

## API 설계 규칙

- API 경로는 `kebab-case` 또는 명확한 명사형을 사용합니다.
- 예: `/policy-list`, `/rag-chat`, `/recommendations`
- 요청 모델과 응답 모델은 분리합니다.
- 응답에는 필요한 데이터만 포함하고 내부 구현 세부사항은 노출하지 않습니다.
- 상태 코드와 오류 메시지는 호출자가 이해할 수 있게 작성합니다.

## 환경 변수와 보안

- `.env`는 직접 커밋하지 않습니다.
- 공유가 필요한 환경 변수 이름은 `.env.example`에 예시로만 작성합니다.
- API Key, DB 비밀번호, Discord Webhook URL 같은 값은 코드에 직접 쓰지 않습니다.
- GitHub Actions Secret이 필요한 값은 Repository Secret에 등록합니다.

## RAG와 데이터 파일

- RAG 관련 코드는 `api/rag` 또는 별도 서비스 계층으로 분리합니다.
- 대용량 원본 문서, 처리된 문서, 임베딩 결과는 Git에 올리지 않습니다.
- 임베딩 결과나 벡터 DB 덤프는 재생성 가능한 산출물로 취급합니다.
- 샘플 데이터가 필요하면 작은 예시 파일만 추가하고 민감정보를 제거합니다.

## 리뷰 기준

- FastAPI 앱 실행에 영향을 주는 변경은 `/`와 `/docs`를 확인합니다.
- 새로운 API는 요청/응답 예시와 오류 상황을 함께 고려합니다.
- 문서, 자동화, 설정 변경은 런타임 코드 변경과 분리해서 PR을 만들 것을 권장합니다.
